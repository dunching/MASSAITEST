## 2. 项目一句话定义

MASSAITEST 使用 `MassAICrowdDemo` 作为验证宿主，最终产品是可复用的 `MassCrowdSimulation` 大规模 Agent Simulation Runtime。

最终架构采用：

```text
Persistent Full Worker Authority
```

每 World 的 Persistent Worker 是日常模拟状态的唯一权威；Mass、Network、Presentation 只承担实体集成、输入输出、代理和表现职责。

## 3. 当前运行模型

多实体处理模型：

```text
Entity
  ↓
Work
  ↓
Shard
  ↓
UE Task
  ↓
Shard-local Output
  ↓
Deterministic Owner Merge
```

不是“一实体一线程”，也不是普通帧无条件扫描全部 Agent。

Worker 主要基础件：

- WorkRing
- TimeWheel
- DependencyIndex
- ResourceStore
- EntityStateStore
- DirtyStateStore
- SpatialIndex
- DeterministicShardPlanner

当前 Domain 顺序：

```text
Lifecycle / Input
→ Behavior
→ Flow / Resource
→ Target
→ Combat / Reactive
→ Movement Planning
→ Movement
→ Particle / Interaction
→ Facing / Finalize
→ Publish
```

Target Region 的正确理解：

> 目标附近的 Target-relative Polar Transport Field。

它使用 Radial Band + Angular Sector 形成 Polar Navigation Cells，通过 Demand Region、Population Deficit/Surplus、Transport Plan 与 Edge Quota 引导大量实体在目标周围自然展开。

它不是永久 Slot，也不是每个 Agent 固定绑定一个 Region owner。

## 9. 修改代码时的硬规则

1. 同一模拟字段只允许一个 Production Writer。
2. Worker 不直接访问 UWorld / Actor / UObject / Mass View。
3. Task 只写 shard-local output，最终由 Owner 稳定 Merge。
4. GT 不把刚消费的 Worker 状态作为普通输入 echo 回 Worker。
5. 所有可失败验证发生在第一次写入前；之后进入 no-fail commit。
6. 旧生产结构被替代后必须物理删除，不保留 wrapper/fallback。
7. Target / Particle 修复禁止按 AgentId、step、地图写特判。
8. 20 实体 PASS 不替代长窗口或 10k 门。
9. runner 返回 FAIL 时不得根据内部日志手工改报正式 PASS。
